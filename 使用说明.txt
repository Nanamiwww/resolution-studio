Resolution Studio 1.5.3 · 空间分辨率分析
=========================================

基于 ImageJ 1.54u 源码构建的空间分辨率分析程序（原 MTF Studio），包含两种测量模式：
· 刃边 MTF：按 ISO 12233 / IEC 62220-1 的刃边法计算调制传递函数；
· 线对卡：沿线对卡取灰度剖面，自动识别每组线对的峰值 / 谷值灰度，计算对比度、CTF 和极限分辨率。
两种模式在窗口顶部切换（Ctrl+1 / Ctrl+2），共用同一张图像和像素尺寸。


一、启动方式
------------
方式 1：独立程序（推荐）
  先把压缩包「全部解压」到一个文件夹，再双击其中的「启动 Resolution Studio」。
  （在压缩包里直接双击是运行不了的，脚本会提示先解压。）
  第一次启动时，脚本会自动寻找电脑上的 Java（Java 8 或更新版本都可以），依次查找：
  已安装的 Java（注册表和常用安装位置）、Android Studio / IntelliJ IDEA 自带的 Java，
  以及 ImageJ / Fiji 自带的 Java——放在桌面、下载、文档、各磁盘根目录，或者与本文件夹相邻，
  都能找到，包括再往下一层的子文件夹（例如「下载\ij154-win-java8\ImageJ」）。
  有多份 Java 时优先用版本较新的 64 位 Java。找到后记在 java-path.cfg 里，以后直接启动。
  想换用别的 Java：删除 java-path.cfg 重新启动，或用记事本把里面的路径改成新的 javaw.exe。

  如果找不到 Java，窗口里会用中文说明，任选一种办法：
  · 把 ImageJ / Fiji 的文件夹（或其中的 javaw.exe）拖进提示窗口，按回车；
  · 直接按回车打开 Adoptium 官网，点「下载 Temurin」，安装后重新双击启动；
  · 把一份 Java 文件夹（含 bin\javaw.exe 的那一层）复制到本文件夹并改名为 jre，即成免安装便携版；
  · 或者改用下面的插件版，直接用 ImageJ 自己的 Java 运行。

  小提示：用 ImageJ 自带的 Java 8 时，如果系统显示缩放大于 100%，窗口由 Windows 放大，
  文字会略微发虚；装一个新版 Java（例如 Temurin 21）并删除 java-path.cfg，就能清晰显示。
  程序出错时会弹窗说明，详细信息写在本文件夹的 resstudio-error.log 里，反馈问题时请附上它。

方式 2：ImageJ / Fiji 插件
  1. 把「插件版」文件夹里的 Resolution_Studio.jar 复制到 ImageJ 的 plugins 文件夹
     （Fiji 则是 Fiji.app\plugins）。如果以前装过 MTF_Studio.jar，可以删掉它，新版已包含全部功能。
  2. 重启 ImageJ，菜单 Plugins → Resolution Studio。
  3. ImageJ 里打开的图像会自动带进来：画了矩形选区就沿用矩形；画了直线选区（含线宽）
     会直接进入线对卡模式。
  注意：插件会把 ImageJ 里 Swing 组件的外观切换成 Resolution Studio 的样式，经典 ImageJ 的主窗口不受影响。


二、打开图像
------------
点「打开图像」或把文件直接拖进窗口。支持 TIFF（含 16 位、多帧）、DICOM、PNG、JPEG、BMP、FITS 等；
无文件头的 RAW 数据会弹出对话框，填写宽、高、位深、字节序和文件头偏移即可；文件比所填格式需要的短时不能导入
（缺的部分不会用 0 补上），实际读到的帧数与所填不符时也不导入。
多帧图像可以在图像标题栏选「全部帧平均」降低噪声。
有符号 16 位数据（RAW 选「16 位有符号」、有符号 TIFF / DICOM）和带线性数值校准的文件（如 DICOM 的 Rescale 截距）
按文件中的实际数值分析（ImageJ 内部存储有符号数据时加了 32768 的偏移，程序会换算回来），状态栏会说明；
非线性的数值校准不采用，按存储的原始数值分析。
彩色图像会自动转为灰度再分析，图像标题栏显示「彩色→灰度」，状态栏说明怎么换算的：
  · 普通彩色（RGB，如 JPEG、PNG、BMP）和 16 位彩色 TIFF：按亮度 Y = 0.299R + 0.587G + 0.114B 换算
    （ISO 12233 对彩色图像的做法）；R = G = B 的“彩色格式灰度图”直接取灰度，数值不变；
  · 调色板（索引色）图像，如 GIF：颜色排列杂乱（普通图片，也包括排列杂乱的灰度调色板）时按各颜色的亮度换算；
    颜色平滑过渡（Fire、Jet 等伪彩色查找表）时认为数值本身是数据，保留原始数值，只把显示改成灰度。
    这是程序的判断，状态栏会注明“自动判断”；
  · 反转灰度查找表（亮处数值小）：TIFF、DICOM 等默认按文件里存的原始数值（ImageJ 的反转查找表、DICOM MONOCHROME1 的约定），
    GIF、PNG、BMP 这类普通图片默认按显示的灰度（255 − 数值）；两种都可以在「颜色」里切换。
  自动判断不对时，在图像标题栏的「颜色」里改：调色板图像可选「按原始数值 / 按调色板颜色的亮度」，反转灰度查找表可选「按原始数值 / 按显示的灰度」，
  RGB 和多通道图像可选「按亮度合成」或只用某一个通道（例如多通道的科学图像）。选择会写进导出文件。
  注意：已经存成 RGB 的伪彩色图（例如截图）转成灰度后数值不是线性的，算出的 MTF 不可信，请尽量用原始灰度数据。
像素尺寸（µm）两种模式共用，属于每一张图像：
  · DICOM 或带标定的 TIFF：自动读取；如果文件里只有普通的分辨率标签（每英寸或每厘米多少像素，例如 300 dpi，
    也就是每厘米 118.11 像素），那通常是打印 / 屏幕分辨率，程序照样换算，但标为“未确认”，确认方式同下；
    在 ImageJ 里设好比例尺保存的 TIFF（ImageJ 的说明信息里写明了单位）按文件里的标定处理；
  · 文件里没有像素尺寸信息：暂时沿用上一张图像（或上次使用）的值，输入框标黄，结果里提示“未确认”。
    没换探测器和放大倍数就点输入框旁的对勾（确认）按钮，否则改成正确的值。换了设备却没改，lp/mm 会整体按错误比例换算；
  · 像素尺寸的来源（从文件读取、手动输入、按已知长度标定、按线对卡反推、沿用）写进导出文件；
  · 确认时可以选“本次运行中之后打开的无标定图像都用这个值”，适合同一台设备拍的一批图像；手动改值或重新标定后恢复逐张确认；
  · 文件里像素宽、高不等（非方形像素）时，输入框里是宽度：刃边按测量方向（水平 / 垂直）换算；
    线对按“剖面在屏幕上与条纹垂直”换算（斜着画也一样），结果卡里会说明用了哪个间距。
    手动输入或按已知长度标定的像素尺寸按方形像素处理（除非当前图像的文件自己写明了宽高不等）。
不知道像素尺寸时，点像素尺寸右边的尺子按钮，按已知长度标定（见第五节）。
输入框里的数值（像素尺寸、线宽、判定阈值、线对卡的整卡标称值、数据表里的标称值、RAW 导入的各项）：
  · 改了数字、还没按回车时，数字显示为蓝色，鼠标停在框上提示“按回车应用，Esc 撤销”；
  · 保存项目、关闭窗口、打开另一张图像或项目、从 ImageJ 导入、导出、复制摘要、加入对比之前，会先像按了回车一样
    应用框里的数字，快捷键、菜单、按钮和窗口的关闭按钮都一样；
  · 输入的不是有效数值（例如 12abc、1e5、整数框里的 2.5）或超出范围时，框标红，鼠标停在上面说明原因；
    这时保存、导出、关闭等会停下来，提示是哪个框、为什么，输入保留，光标回到框里：改正后按回车，或按 Esc 撤销；
  · 全角数字和中文输入法的小数点（１２．５、12。5）按半角处理；“Infinity”“NaN”“2.5f”“0x10”之类不算数值；
  · 切换模式或主题、点到别的输入框或图像上时，能应用的数字同样应用；不能应用的恢复原来的值
    （切换模式和主题时状态栏会说明）。线对卡的整卡标称值例外：点到别处时，不能采用的列表留在框里、保持红色，
    直到改正或按 Esc（切换模式和主题时同样恢复并说明）；
  · 标定窗口的「实际长度」边输入边应用（不显示蓝色）；输入无效时同样标红，点「应用到像素尺寸」会提示。


三、线对卡模式
--------------
1. 切到「线对卡」，剖面工具选「直线」，在图像上沿线对方向画一条线，横穿要分析的线对组，
   尽量与线条垂直（按住 Shift 保持水平 / 垂直 / 45°）。拖动端点可调整，方向键可平移。
   线对卡在图像里是斜的（摆歪了几度，或按惯例斜放 45°）也没关系：打开图像时程序会自动检测倾斜角，
   把画面转正，直接画水平线或框矩形即可（「画面方向」里可以关掉；图像上方的「摆正」按钮随时切换）。
   摆正只旋转显示，剖面直接取原始像素、沿条纹法线投影计算，不做插值，所以对比度不会因此降低；
   倾斜时像素落在不同的亚像素位置，剖面还能按 0.5 像素间隔采样（与刃边法的过采样同一个原理）。
2. 线宽 = 沿线条方向平均的像素数。线条较长时设大一些（例如 20～60），噪声会明显降低。
   改线宽时，手动分组、删除、改过的标称值和手动指定的参照组按位置重新套用；暂时套不上的不应用、但仍保留
   （随项目保存，线宽改回时恢复），状态栏会说明。保存、导出、关闭前自动应用的线宽有套不上的，会先说明并问要不要继续。
   也可以改用「矩形」，框住线对区域，程序自动沿垂直于线条的方向对整块区域求平均。
3. 程序会立即画出灰度剖面，自动找出峰和谷、按条纹间距分组，并在图像和剖面图上用色块标出每组：
   · 每组的峰值 / 谷值灰度均值（及标准差）、峰谷差；
   · 对比度 = (Imax − Imin) / (Imax + Imin)；
   · CTF = 该组峰谷差 ÷ 参照组峰谷差（参照组默认是最低频的可信组，也可以手动指定，见第 6 条）；
   · MTF 估算 = 用 Coltman 级数由 CTF 换算（勾选「Coltman 换算 MTF」可在图中显示）。
4. 在「标称值」里填入卡上标注的各组 lp/mm（例如 1, 1.5, 2, 2.5 …），改完按回车，程序会按顺序把识别到的组
   对齐到标称值，频率以标称值为准；像素尺寸未知时，还会据此反推像素尺寸，点「采用」即可。
   各项用逗号、顿号、分号或空格分隔，全角数字和全角标点也可以；与其他输入框一样，没按回车的列表是蓝色，
   保存、导出、关闭、切换模式前自动采用，Esc 撤销。每一项都要是正数：有一项不能识别（如 2abc、0、Infinity），
   整份列表就不采用——框标红，提示指出是哪一项，分析仍按正在使用的列表，保存、导出、关闭会停下来说明；
   不会只用能识别的那几项（1.5.2 会悄悄跳过，例如把 7 打成 7abc 时会把 8 当成下一组）。
   导出的 CSV、复制的摘要和图表说明都写明实际采用的标称值。
5. 极限分辨率按「判定标准」计算（默认 CTF ≥ 10%，可改为对比度、可改阈值），结果卡注明是怎么得出的。
   真实的极限一定在最后一个达标的组和第一个不达标的组之间（假设 CTF 随频率单调下降）：
   · 两组频率相差不超过 1.3 倍时，在两者之间线性插值，给出一个数值——两组都是实测的；
     CTF 在频率较高处是下凸的曲线，直线插值略偏高（理论上 1.3 倍时最多约 +7%）；
   · 两组相差超过 1.3 倍（例如自己填的稀疏标称值 1, 2, 4, 6）时只给「区间」，如 2.00～4.00：
     间隔越宽，直线插值偏高越多（1.5 倍时约 +11%，2 倍时达 +34%），所以不给单一数值；
   · 「≥」下限：测到的组全都达标，更高的组没测到。原因可能是没填标称值、剖面上没有完整的下一组（没覆盖到或被截断）、
     可用的组少于两个、下一组接近奈奎斯特频率（采样相位可能把调制抹掉）、噪声太大（达标的弱组也可能识别不出），
     或下一组所在的那一段里还有明显的峰谷（没能分组的线对或文字标记，可以在剖面图上手动框出）。
     下限只说明“至少这么高”，把剖面延长或降低噪声再测；
   · 「≈」估计：填了标称值，最高的已测组之后，剖面上能看到一段完整的“灰块”——分辨不出的组就是这样：
     灰度在背景和线条之间、长度与下一组相当、里面没有明显的峰谷，剖面越过了它的两端，而且在剖面两侧约 1 mm 处
     也看得到它（线条是长的，文字标记之类的短结构不是）；同时下一组离奈奎斯特频率还远，噪声也够小（识别门限不到判定标准的一半）。
     这时真实极限在最后达标的组与这一组之间；两组相差不超过 1.3 倍时按该组 CTF≈0 线性插值给出估计值，
     相差更多时同样只给区间。那一组往往还有一点识别不出的调制，所以估计值通常略偏低。前提是这段灰块确实是下一组
     （例如两排排列的卡，下一组可能在另一排）。
   数据含负值时 (Imax−Imin)/(Imax+Imin) 没有意义，程序会提示改用 CTF 判定。
6. 沿卡的方向，各组频率应当单调变化。不符合这个顺序的组标为
   「疑似混叠」（接近奈奎斯特之后频率反而回落）或「疑似误识别」（例如条纹前背景里噪声起伏凑成的“组”），
   在列表里标出（圆点变灰），不计入 CTF 参照、极限分辨率和 MTF 估算。
   参照组：点分组列表里某一组的小旗按钮，就以它的峰谷差为 100%；再点一次恢复自动选择。
   自动分组不理想时：在灰度剖面图上拖动鼠标，可以手动框出一组；在「线对分组」列表里可以删除多余的组；
   「重新自动识别」恢复自动结果。数据表里的「标称」一列可以直接改。
7. 「对比度曲线 CTF」图可勾选「叠加刃边 MTF」，与刃边模式的测量结果画在一起比较。
8. 导出：灰度剖面数据（每个位置的灰度值和所属分组）、分组结果（CSV，Excel / Origin 可直接打开）、
   图表 PNG（白底），或复制结果摘要。导出内容都带上软件版本、图像和帧、颜色与数值的处理方式、
   像素尺寸及来源、质量状态、全部警告，分组结果还写明极限分辨率的类型和得出方式（插值 / 估计 / 区间 / 下限及其假设）、
   所在区间、参照组和是否计入。图表 PNG 的下方附一段文字说明这些信息；CTF 图上叠加的刃边曲线也逐条写明。


四、刃边 MTF 模式
-----------------
1. 在图像上框选一段略微倾斜的刃边，结果立即算出；黄色虚线是拟合出的刃边位置。
   竖直刃边测水平方向 MTF，水平刃边测垂直方向 MTF，程序自动判断。
   刃边模式默认不旋转图像：过采样靠的就是刃边相对像素的真实倾斜，事后旋转要插值，会把插值的模糊算进 MTF。
   倾角提示不合适时（小于 1° 或大于 10°），请调整刃边的摆放角度后重新拍摄。
2. 结果：MTF20、MTF10（极限分辨率）、奈奎斯特处 MTF、刃边倾角、LSF 半高宽、对比噪声比；
   MTF 图上的两条虚线分别是 20% 和 10%。
   倾角不合适、饱和、噪声大时会用黄色提示。亚像素采样的提示分两级：
   「严重不足」（刃边在选区内横移不到半个像素）时 MTF 不可靠；「偏少」时缺的亚像素位置靠插值补齐，偏差通常不大。
   倾角正好落在 14°、18.4°、26.6°、33.7°、45° 这类“整齐”的斜率附近（斜率接近 1/4、1/3、1/2、2/3、1 等）时，
   各行只重复几种亚像素位置，也会提示：这时标准方法的 MTF20 / MTF10 可能偏差几个百分点甚至更多。
   倾角大（10°～45°）而不在这类斜率上并不影响精度：程序按到刃边的垂直距离投影，测得的就是刃边法线方向的 MTF
   （模拟 10°～45° 的刃边：偏差 ≤ 0.5%），模糊各向同性时与水平 / 垂直方向相差在 1% 以内；但 IEC 62220-1 要求约 1.5°～3°。
3. 「加入对比」可叠加多条曲线；对比列表随项目一起保存（见第六节），有没保存的记录时关闭窗口会先提醒。
   每条记录保留加入时的像素尺寸，之后改像素尺寸不会改变它；加入时没有像素尺寸的记录，图中按当前像素尺寸换算并在图例注明。
   记录旁的黄色三角表示需要注意（像素尺寸未确认、亚像素采样不足、旋转计算、可能饱和等），鼠标停在上面可看详情。
   导出 MTF / ESF / LSF 数据、对比曲线和图表时，同样带上版本、图像和帧、像素尺寸及来源、质量状态和全部警告；
   对比图 PNG 的下方逐条写明每条曲线（按图例名称）的这些信息，没有当前选区、只剩历史曲线时也一样。
4. 旋转计算（实验性，默认关闭）：在「测量参数 → 旋转计算」勾选，会先弹出提示，确认后才开启；
   每次启动程序都恢复为关闭。开启后，只在亚像素采样严重不足时才旋转，包括两种情况：
   ① 刃边几乎与像素行 / 列平行（倾角小于 2°，刃边在选区内横移不到半个像素）；
   ② 倾角正好落在上面说的“整齐”斜率附近（各行只重复几种亚像素位置），不管角度大小。
   旋转时把选区用三次卷积插值转到约 4° 再计算，并按插值核的频率响应补偿插值的模糊。其他选区照常计算，结果不受影响，
   结果卡里会说明没有旋转的原因。倾角大但不在“整齐”斜率上时不旋转：旋转改变不了测量方向（仍是原刃边的法线方向），
   只会多一次插值（模拟：转到 4° 后偏差反而略增，约 0.1%～1.5%）。
   “整齐”斜率的模拟结果（σ = 0.6～1.1 像素）：标准方法的 MTF20 / MTF10 偏差 2%～50%（如 26.6° 时 MTF10 偏 43%，
   45° 时约 −11%），旋转后 ≤ 2%。
   用模拟刃边（先模糊、后按像素采样）验证 0° 刃边：标准方法的 MTF20 / MTF10 偏低约 5%～10%；旋转后，
   模糊的系统（奈奎斯特处 MTF ≤ 0.03）MTF20 偏差 ≤ 0.5%、MTF10 ≤ 1.2%。较锐利的系统（奈奎斯特处 MTF ≈ 0.19）
   的 MTF20、MTF10 落在奈奎斯特附近或以上，旋转也给不出可靠值（误差可达 50%）；这时结果卡会在数值下方注明
   「近奈奎斯特，旋转后可能不准」或「超过奈奎斯特，旋转后不可信」。
   原始采样里缺失的亚像素信息和混叠无法恢复：接近奈奎斯特（约 0.7 倍以上）的部分误差可能很大（较锐利的系统可差一倍），
   奈奎斯特以上的曲线不可信；LSF / ESF 图和 LSF 半高宽含插值的展宽。
   这类结果只作粗略参考，不能代替按 2°～5° 倾斜摆放的刃边测量，也不宜与标准方法的结果直接比较；
   保存、导出和摘要里都会注明「旋转计算（实验性）」。


五、像素尺寸标定（按已知长度）
------------------------------
1. 点「像素尺寸」右边的尺子按钮，弹出标定窗口（停在右侧，不挡图像）。
2. 在图像上沿一段实际长度已知的距离画一条线，例如刃边板的宽度或全长、尺子上两条刻度之间。
   量板长时，把线画在板内、与板边平行，两端略微超出板的两头即可。线越长越准；可以拖动端点微调，滚轮放大。
3. 「端点自动对齐到明暗边界」（默认勾选）：两端各自移到附近边缘的半灰度处，精度可达亚像素，
   与边缘模糊的程度无关。量刻度线中心之类的细线时请取消勾选。
4. 填入实际长度（mm），窗口里立即显示像素尺寸；点「应用到像素尺寸」填入，两种模式都用这个值，来源记为“按已知长度标定”。
   取消或切换模式时，像素尺寸不变；打开新图像时按第二节的规则处理（文件里有就读取，没有就沿用并提示确认）。
注意：被测物体不贴着探测器时有几何放大，得到的是物体所在平面的像素尺寸。
      线要与被测长度的方向一致：板是斜放的，就沿板边画，不要按 Shift 画成水平线（偏 3° 会长 0.14%）。


六、项目（保存与恢复整个分析）
------------------------------
点顶部的「项目」→「保存项目」（Ctrl+Shift+S），把当前分析保存为 .rsproj 文件（文本格式），内容包括：
  · 图像的位置（绝对路径和相对项目的路径）、文件大小和 SHA-256 校验值，RAW 数据的格式参数；
  · 帧和多帧平均、颜色处理方式、像素尺寸及来源（包括“沿用，未确认”的状态）、线对卡的摆正角度；
  · 刃边的选区和测量参数；线对卡的剖面线或矩形、线宽、灵敏度、判定标准、标称值、手动指定的参照组，
    以及手动分组、删除和改过的标称值；
  · 全部对比记录（含完整的 MTF / ESF / LSF 曲线、像素尺寸来源和警告），以及每条记录自己的图像文件：
    位置、大小、SHA-256、RAW 格式参数、帧和颜色处理（来自其他图像的记录也一样，1.5.3 起）。
「打开项目」（Ctrl+Shift+O，或把 .rsproj 文件拖进窗口、拖到启动脚本上）会先按相对路径、再按原来的绝对路径找图像，
核对文件是否与保存时相同，然后按项目里的参数重新计算，状态栏会说明结果是否与保存时一致：
  · 图像改过（大小或校验值不同）：先提示，可以选择仍然打开，这时会列出哪些结果变了；
  · 找不到图像：可以手动找到它，或只恢复项目里的对比记录（当前窗口里的分析不变）；
  · 对比记录的图像文件也逐个核对（先按相对项目的路径、再按原来的绝对路径找）：打开报告列出其他图像是“一致”“已改变”
    “找不到”还是“无法核对”（没有校验值）；记录的提示里写明来源文件和核对结果，找不到或已改变的记录旁有图标；
    导出的对比 CSV 也逐条写明来源文件、SHA-256 和核对结果。记录里的曲线和结果照常可以查看、导出，
    只是无法再用原图核对或重新计算。1.5.2 及更早保存的记录只有图像名称，标为“未记录”；
  · 打开项目或图像要在后台读一会儿：读取期间又改了当前分析（输入数字、画选区、加入对比……），替换之前会再问一次
    “保存 / 不保存 / 取消”，选取消就保留当前分析、放弃这次打开（1.5.2 只在加了记录时问，其他改动直接被替换）。
图像的校验值在打开图像时就在后台算好；保存时图像文件已被移走或改动，项目照样保存，只是不带校验值（状态栏会说明）。
图像本身不复制进项目，请把项目和图像放在一起保管（一起搬到别的文件夹或电脑也能找到）。
打开另一张图像即开始新的分析，再保存时会询问新的项目文件名。
未保存的改动：保存或打开项目之后，只要项目里保存的内容有了变化——像素尺寸及其来源和确认、选区和剖面、帧和颜色处理、
  测量参数、线对的手动修改和参照组、对比记录的增加、删除（包括删到一条不剩）、改名和显示 / 隐藏——标题栏就显示
  “（未保存）”；这时关闭窗口、打开另一张图像或另一个项目，会先问「保存 / 不保存 / 取消」。改了又改回原样不算改动；
  只切换刃边 / 线对模式、图表页，或线对卡模式第一次打开时的自动摆正，也不算。保存期间又做的改动不在刚保存的文件里，
  仍算未保存。没有关联项目时，只在加入对比的记录还没保存过时提醒（打开新图像时记录会保留，不提醒）。
  输入框里改了还没按回车的数字，在保存和这些提醒之前先应用，同样算改动（见第二节末）。


七、怎样测得准
--------------
· 数据要线性：尽量用原始数据并做好暗场、增益（平场）校正；避免饱和、JPEG、锐化或伽马处理。
· 像素尺寸要准：lp/mm 表示的频率与像素尺寸成反比；不确定时用尺子按钮按已知长度标定。
  需要预处理时点「ImageJ」→ 打开经典 ImageJ，处理后再「导入 ImageJ 中的当前图像」。
· 刃边：常用 1 mm 厚钨板紧贴探测器，相对像素行或列倾斜约 2°～5°（IEC 62220-1 推荐约 1.5°～3°）。
· 线对卡：剖面线与线条垂直；接近奈奎斯特频率的组读数受采样相位影响，高于奈奎斯特会出现混叠，
  程序会在备注里提示。3 线一组的线对卡，外侧线条受背景影响，CTF 会比无限长光栅略低，属正常现象。


八、算法与精度
--------------
刃边：逐行导数质心定位刃边 → 直线拟合 → 沿法线投影 4 倍过采样得 ESF → 差分得 LSF → 加窗傅里叶变换。
  用已知模糊的模拟刃边验证：奈奎斯特以内与理论 MTF 偏差 < 0.007，MTF20、MTF10 偏差 < 1%。
  旋转计算（实验性）的验证结果见第四节第 4 条。
像素尺寸标定：沿线每 0.25 像素取灰度（垂直方向 5 像素平均），找离端点最近的明显台阶，取半灰度交点。
  用模拟钨板（长 500～900 像素，不同模糊和噪声）验证：端点点偏 ±6 像素以内，测得长度误差 < 0.3 像素（< 0.05%）。
线对卡：按剖面噪声自适应设定门限找峰谷，以半高中心定位，按间距分组（排除外侧线条后估计周期），
  并检查线 / 空占空比、间距均匀性和灰度一致性以排除伪组；再按“沿卡频率单调”检查各组，
  每次去掉与其他组矛盾最多的一组（同样多时先去掉信噪比低、峰谷宽窄不一的），剩下的组定出卡的方向。
  用模拟线对卡验证：可分辨组的实测频率误差 < 1%，标称值对齐与像素尺寸反推（误差 < 0.1%）均正确；
  36 张不同噪声、线宽的模拟卡上，噪声凑成的伪组全部被排除，6 lp/mm 以下的真实组没有被误排除。
  极限分辨率（模拟卡，高斯模糊 σ 1～3.5 像素、步长 0.1，CTF 10%，组间 1.2、1.25、1.3 倍的卡、常用的 1～10 lp/mm 卡
  和稀疏的 1, 2, 4, 6 等，两个扫描方向，有无噪声，共约 600 个结果）：
  · 每个区间都包含 3 线组在本程序中实际测得的极限；
  · 给出单一数值时（插值或估计），与 3 线组的实际极限相差 −4%～+5%；
  · 与无限长方波的理论极限比：3 线组的极限本身就低约 2%～5%（个别 7%），单一数值在 −7%～+2% 之间，
    区间端点最多差约 5%；更模糊的系统或更低的判定阈值下，纯理论的插值偏差可达约 +7%。
    所以单一数值请按“约 ±7%”理解，要更准就用组间更密的卡。
    这些数字只说明程序在上述模拟条件下的表现，不是实测图像的误差保证：非高斯的模糊、背景不均、曝光非线性、
    每组线数不同等都会带来额外的偏差。
回归测试：源码包里的 Regression 测试覆盖上面的精度验证和 1.3.3、1.4、1.5、1.5.1、1.5.2 审查报告指出的各项问题，每项带容差，
  任何一项不通过构建即失败（build.sh、make_release.sh 都会先跑它）。
